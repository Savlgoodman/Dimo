# 工作区侧边栏与页块布局

状态：核心结构已实现，工作区边缘使用按页块尺寸计算的 20% 梯形吸附区，页块分裂使用 30% 边缘区。

## 1. 目标

本设计整理工作区内三类对象的关系。

- **侧边栏**负责导航、文件树、Git、搜索、会话列表等工具面。
- **工作区**负责承载可打开内容和标签页。
- **页块**是工作区内一个可见矩形区域。页块可以拥有多个标签页，也可以通过拖拽标签页与其他页块形成新的分裂布局。

侧边栏与工作区都可以拥有自己的尺寸和视觉边界，但二者的布局生命周期、拖拽规则和持久化状态彼此独立。

## 2. 对当前实现的理解

当前实现已经具备 Dockview、标签页、分组、左右上下分裂、布局序列化、工作区画布和侧栏内部面板拖拽等能力。

当前主要问题在于职责混合。

- `WorkspaceActivityRail` 只渲染侧栏图标，但侧栏内容组仍由 Dockview 的左侧 group 承载。
- 工作区页块、右侧会话栏、底部终端栏和左侧工具面都进入同一个 Dockview 网格。
- Dockview 因此需要同时处理“侧栏自身布局”和“标签页工作区布局”。侧栏移动、隐藏、恢复和工作区分裂会互相影响尺寸与组顺序。
- 工作区圆角、Dockview sash 和侧栏边缘由多个 CSS 层共同修正，容易出现圆角位置与拖动条高度不一致。

这解释了截图中侧栏和标签页争抢横向空间的现象。问题的根源是布局所有权没有被切开。

## 3. 目标布局

建议把页面主结构收敛为下面的关系。

```text
WorkspaceShell
├── Topbar
└── MainRow
    ├── Sidebar
    │   ├── SidebarHeader
    │   │   └── SideToggleButton
    │   └── SidebarContent
    ├── SidebarWorkspaceSash
    └── WorkspaceSurface
        └── WorkspaceFrame
            └── DockviewWorkspace
```

侧边栏和工作区是 `MainRow` 的两个并列子容器。Dockview 只存在于 `WorkspaceSurface` 内部，侧边栏不再成为工作区的一个 Dockview group。

侧边栏在左侧时，布局顺序为 `Sidebar → Sash → WorkspaceSurface`。侧边栏在右侧时，布局顺序为 `WorkspaceSurface → Sash → Sidebar`。切换位置只改变外层顺序和边缘样式，不改变工作区内部的页块布局。

## 4. 术语与职责

### 4.1 侧边栏

侧边栏是工作台级容器，包含活动图标、工具面和侧边栏内部面板。

- 侧边栏拥有自己的可见性、宽度、左右位置和内部面板顺序。
- 侧边栏内部可以继续使用现有的面板排序、上下或左右分裂能力。
- 侧边栏中的面板不能通过工作区的页块拖拽逻辑分裂到工作区。
- 侧边栏右上角的现有拖动语义改为位置切换按钮。按钮点击后在左侧和右侧之间切换。
- 位置切换不应重建或重排工作区内的页块。

“右上角”应理解为侧边栏靠近工作区一侧的上部控制区。侧边栏在左侧时按钮位于侧边栏右上方，侧边栏在右侧时按钮位于侧边栏左上方。这样按钮始终靠近侧边栏与工作区的交界处。

### 4.2 工作区

工作区是独立的内容布局容器。它负责页块、标签页、页块分裂、拖拽预览和布局恢复。

- 工作区不感知侧边栏内部的 group。
- 工作区的外边界尺寸由外层 flex 布局决定。
- 工作区内部的每一个可见矩形区域都是一个页块。
- 工作区允许存在多个页块。
- 工作区边缘吸附与页块边缘吸附属于同一次拖拽判定。页块边缘 0%-30% 用于分裂，其中靠近工作区边缘的 0%-20% 优先归属于工作区吸附，重叠处使用梯形区域和距离优先级消歧。

### 4.3 标签页与页块

- **标签页**是一个可打开的内容项，例如文件预览、对话、终端或插件面板。
- **页块**是标签页的承载区域。一个页块可以有 `n` 个标签页，其中只有一个标签页处于当前展示状态。
- 拖拽标签页到另一个页块的中心区域时，标签页加入目标页块，形成同一组标签。
- 拖拽标签页到目标页块的上下左右边缘时，目标页块分裂为两个页块。拖拽中的标签页成为新页块的内容。

从用户视角看，页块之间是平级的空间区域，没有业务上的父子关系。为了保存布局和恢复尺寸，实现内部仍需要使用分裂树或等价的序列化结构表达“哪一次分裂产生了哪两个矩形区域”。这个内部结构只服务于几何布局，不表达内容归属关系。

## 5. 侧边栏与工作区的交界

### 5.1 圆角

工作区的外层容器负责圆角。与侧边栏相邻的一侧使用直角，远离侧边栏的一侧保留工作区圆角。

| 侧边栏位置 | 工作区保留圆角 | 工作区与侧边栏相邻边 |
| ---------- | -------------- | -------------------- |
| 左侧       | 右上角、右下角 | 左上角、左下角为直角 |
| 右侧       | 左上角、左下角 | 右上角、右下角为直角 |

这条规则作用于 `WorkspaceFrame`，不依赖 Dockview 内部 group 的圆角。Dockview 的页块和标签栏应当服从工作区外层容器的裁剪。

### 5.2 交界拖动条

侧边栏与工作区之间保留一个可调整宽度的 sash。sash 的有效可视高度必须等于工作区去掉相邻圆角后的直线高度。

```text
侧边栏在左侧

┌──────────────┬──────────────────────────╮
│              │                          │
│   Sidebar    │       Workspace          │
│              │                          │
└──────────────┴──────────────────────────╯
               ↑
          sash 只覆盖直线段
```

```text
侧边栏在右侧

╭──────────────────────────┬──────────────┐
│                          │              │
│       Workspace          │   Sidebar    │
│                          │              │
╰──────────────────────────┴──────────────┘
                           ↑
                      sash 只覆盖直线段
```

sash 的命中区域可以比可视线略宽，但背景线、hover 线和拖动反馈不能越过工作区的圆角端点形成“飞刺”。

## 6. 工作区内部布局模型

### 6.1 外层容器与页块布局分离

工作区外层只负责容纳 Dockview 和提供边界尺寸。Dockview 内部只管理页块和标签页。

```text
WorkspaceFrame
└── DockviewWorkspace
    ├── PageBlock A
    │   ├── Tab A1
    │   └── Tab A2
    ├── PageBlock B
    │   └── Tab B1
    └── PageBlock C
        ├── Tab C1
        └── Tab C2
```

页块的布局可以用递归分裂树理解。

```text
Split(horizontal, 42%)
├── PageBlock A
└── Split(vertical, 55%)
    ├── PageBlock B
    └── PageBlock C
```

用户看到的是三个平级页块。树只用于保存分裂方向、比例、叶子内容和恢复顺序。

### 6.2 页块操作

拖拽一个标签页时，目标页块有五类结果。

| 目标区域 | 结果                                                   |
| -------- | ------------------------------------------------------ |
| 中心区域 | 标签页加入目标页块的标签组，激活行为沿用现有标签页交互 |
| 上边缘   | 目标页块上下分裂，拖拽标签页位于上方                   |
| 下边缘   | 目标页块上下分裂，拖拽标签页位于下方                   |
| 左边缘   | 目标页块左右分裂，拖拽标签页位于左侧                   |
| 右边缘   | 目标页块左右分裂，拖拽标签页位于右侧                   |

这里的“中心区域”不是新增的独立 UI。它指目标页块排除四周分裂区后剩下的区域。标签页拖到这个区域，表示“放入这个页块”，与点击目标页块的标签栏并列，而不是创建新页块。

分裂后，新页块的初始尺寸使用目标页块对应方向的一半。用户随后可以拖动两个相邻页块之间的 sash 调整边界。拖拽过程只移动标签页，不移动整个页块。

### 6.3 页块尺寸与空页块

页块之间的尺寸调整沿用当前 Dockview 的相邻 sash 方案。sash 属于相邻页块之间的共享边界，拖动时同步改变边界两侧的尺寸，并保持其他页块的布局关系。

最小尺寸采用局部布局方向的格数约束。

- 左右分裂时，每个页块至少保留工作区可用宽度的 `1/5`，相当于横向最多稳定容纳 5 个最小页块。
- 上下分裂时，每个页块至少保留工作区可用高度的 `1/4`，相当于纵向最多稳定容纳 4 个最小页块。
- 实际计算还要服从当前 Dockview 的最小像素宽高约束。百分比约束和像素约束同时存在时取更严格者。
- 如果新分裂会让任意一侧低于最小尺寸，则不执行分裂，继续按中心区域处理或保持当前预览。

拖拽页块中的最后一个标签页时，源页块在移动成功后立即消失。任何没有标签页的普通页块都不能继续保留、显示或写入持久化布局。清理空页块后，周围的分裂节点需要压缩，避免留下空白区域。

工作区始终保留至少一个可接收新标签页的页块。

## 7. 拖拽吸附与命中区域

### 7.1 命中判定的层级

为避免工作区边缘与页块边缘同时命中，建议固定以下优先级。

1. 先判断拖拽指针是否进入工作区边缘带。
2. 如果没有命中工作区边缘带，再判断目标页块的四个分裂区域。
3. 如果没有命中分裂区域，则使用页块中心区域进行标签合并。

工作区边缘带优先于页块边缘带。这样靠近工作区最外侧时，用户明确表达的是占用整个工作区边缘，而不是在贴边页块内部继续分裂。

### 7.2 推荐的归一化区域

用户提出的百分比可以统一解释为相对于当前命中页块或工作区的边缘距离。

- **工作区边缘带**：从工作区边界向内的 `0%–20%` 区域。
- **贴边页块的分裂带**：当目标页块贴着对应工作区边缘时，使用该页块从自身边缘向内的 `20%–50%` 区域。
- **非贴边页块的分裂带**：使用该页块从自身边缘向内的 `0%–35%` 区域。
- **页块中心区**：排除分裂带和工作区边缘带后的剩余区域。

这里的百分比是命中区域的计算规则，不是把视觉 UI 缩放成百分比。实现时需要把百分比换算成像素，并设置最小与最大像素值，避免超宽工作区或极窄页块导致命中区失真。

### 7.3 角落的梯形区域

在工作区角落，水平边缘和垂直边缘会同时竞争。建议使用两个边缘带的线性边界形成梯形或四边形命中区。

```text
工作区左上角

┌───────────────╮
│\\  工作区上边缘区
│  \\
│    ┌────────── 页块边缘区
│    │
│    │  中心区
```

判定原则如下。

- 指针更靠近工作区外边界时，选择工作区边缘分裂。
- 指针离开工作区边缘带后，选择页块边缘分裂。
- 指针落在两个区域的分界线上时，保持上一次预览结果，避免拖拽时在两个方向之间抖动。
- 四角预览必须明确显示最终会占用的半区，不能只显示一条边线。

### 7.4 拖拽预览

拖拽标签页时显示虚线框放置提醒。虚线框表示松开指针后标签页将进入的最终区域，拖拽过程中不提前改变实际布局。

- 工作区边缘命中显示覆盖整个工作区高度或宽度的半区虚线框。
- 页块边缘命中显示目标页块被分裂后的半区虚线框。
- 中心命中显示目标页块的整体边界或标签组放置提示，表示标签页会加入该页块。
- 虚线框的四个角必须与目标区域一致，不能显示超出圆角或越过相邻页块的线段。
- 预览区域使用当前设计系统中的激活色和表面色，不新增局部颜色。
- 预览目标在指针短暂停留或跨越阈值后才切换，避免边界抖动。
- 松开时再次执行同一套命中和最小尺寸校验，预览结果不能绕过约束。

### 7.5 工作区边缘与页块边缘的竞争

工作区边缘带优先于页块边缘带。贴着工作区外边缘移动时，指针表达的是占用工作区边缘。离开工作区边缘带后，才允许触发贴边页块内部的分裂。

拖拽标签页不会移动整个页块。若用户需要改变页块大小，只能拖动页块之间的共享 sash。

## 8. 布局持久化

侧边栏和工作区使用两份独立状态。

### 8.1 侧边栏状态

- `side`: `left` 或 `right`
- `visible`
- `width`
- 内部面板顺序
- 内部面板分裂方向与尺寸
- 当前激活的工具面

### 8.2 工作区状态

- 页块分裂结构
- 每个分裂节点的方向和尺寸比例
- 每个页块的标签页顺序
- 每个页块的激活标签页
- 每个标签页已有的 Dockview 面板状态

工作区状态仍可继续使用 Dockview 的序列化格式。迁移重点是让序列化根节点只代表工作区，不再把侧边栏 group 放入同一个根布局。

## 10. 参考模型

### VS Code Workbench

VS Code 将编辑器区域、主侧栏、辅助侧栏和面板视为不同的工作台区域。视图可以在区域之间移动，但区域本身有独立的布局职责。这个模型支持本设计中的“侧边栏与工作区分开，标签页只在工作区内分裂”。

### Dockview

Dockview 已经提供标签页、group、上下左右分裂、拖拽覆盖层和布局序列化。当前代码也已经围绕 Dockview 建立了面板恢复、尺寸记忆和分裂测试。因此工作区内部优先继续使用 Dockview，减少新增布局引擎。

### FlexLayout 类树模型

FlexLayout 等项目把布局保存为由行、列和 tabset 组成的模型。这个模型说明“无限嵌套”在持久化层面必须有递归结构，即使产品语义只强调平级空间关系。

## 11. 已确认的产品决策

以下决策已经确认，并作为后续实现的输入。

1. 左右侧边栏都需要记忆自己的宽度。切换侧边栏位置时，恢复对应一侧最近使用的宽度。
2. 侧边栏允许完全隐藏。这是现有能力，改造后继续保留。
3. 拖拽标签页到目标页块的中心区域，表示加入目标页块的标签组。这里的中心区域就是排除四周分裂带后的剩余区域，不创建新页块。标签激活行为沿用现有标签页交互。
4. 不支持拖动整个页块。页块大小只通过相邻页块之间的 sash 调整。
5. 页块没有标签页后立即完全消失，并压缩周围的分裂结构。
6. 所有页块保持横平竖直的矩形网格关系，不出现自由浮动、斜向排列或任意重叠。
7. 按当前讨论的解释，页块最小尺寸按局部布局方向约束。左右分裂时按可用宽度的 `1/5` 计算，上下分裂时按可用高度的 `1/4` 计算，同时服从现有 Dockview 的最小像素约束。
8. 吸附百分比按拖拽指针到工作区或页块边界的距离计算。
9. 会话、终端、插件和文件等内容都视为普通标签页，支持进入任意页块。
10. 拖拽标签页时必须显示虚线框放置提醒，虚线框表示松开后的最终占用区域。

## 12. 开源方案核对

### Dockview

Dockview 与当前代码的契合度最高。它已经提供标签页组、上下左右分裂、相邻 sash、最小尺寸约束、拖拽覆盖层和布局序列化。当前仓库也已经围绕它实现了面板恢复、group 规范化、尺寸记忆和分裂测试。

后续优先继续使用 Dockview，把它的根布局收窄为工作区布局，并把侧边栏移到 Dockview 外层。工作区页块使用 30% 的边缘分裂激活区，靠近工作区边缘的页块再从其中划出按页块尺寸计算的 20% 梯形吸附区。已有的 Dockview 虚线覆盖层样式继续作为放置提醒，工作区保留现有标签拖动辅助层。

### VS Code Grid / Workbench

VS Code 的工作台区域划分和相邻 sash 交互适合参考外层结构与尺寸调整方式。它的编辑器组也是矩形网格，区域之间通过共享边界调整大小，符合“标签页移动、页块边界调整”的交互分工。

VS Code 的完整工作台实现依赖自己的 Grid、编辑器组和序列化体系。直接替换 Dockview 会重复实现当前项目已经具备的面板生命周期、标签页和恢复逻辑，因此暂不建议引入。

### FlexLayout

FlexLayout 采用行、列和 tabset 组成的递归布局模型，适合参考持久化结构。它表达了页块的嵌套分裂关系，也支持 tabset 内的标签页。

它与当前 Dockview 的能力重叠较大。若切换到 FlexLayout，需要迁移现有 Dockview 面板注册、面板参数、恢复逻辑、插件面板和大量测试，收益不足以抵消迁移成本。

### Golden Layout

Golden Layout 同样提供 row、column、stack、标签页、拖拽和尺寸调整，适合验证这种产品形态可以由成熟的分割布局模型实现。

它仍然需要重新接入当前 Dockview 面板体系和工作区状态，因此更适合作为交互参考或未来替代引擎候选，而不是本次修复的直接方案。

### React Mosaic

React Mosaic 更偏向可调整的平铺窗口树，适合验证递归分裂、相邻区域调整和网格约束。它的默认模型更接近窗口平铺，需要额外补齐标签页组、面板注册、拖拽虚线框和当前项目的持久化语义。

## 13. 当前实现边界

当前继续沿用 Dockview，侧边栏和工作区已经拥有独立的容器、API 和持久化状态。

1. 侧边栏位于 Dockview 根布局之外，支持左右切换、双侧宽度记忆、完全隐藏、独立内部面板布局和交界 sash。
2. 工作区 Dockview 只承载工作区页块和标签页。空页块由现有清理流程移除，页块之间通过 Dockview sash 调整。
3. 工作区页块分裂边缘按 30% 命中。贴近工作区边缘的页块将外侧 20% 交给工作区吸附，重叠区域使用梯形法则和边缘距离优先级处理。侧边栏内部继续使用独立的 Dockview 边缘命中。
4. 工作区与侧边栏沿用现有虚线覆盖层和标签拖动辅助层，释放时仍由 Dockview 完成目标校验和分裂。
5. 旧序列化布局中的侧栏 group 会在恢复时迁移到独立侧边栏，工作区布局和侧边栏布局分别保存。
